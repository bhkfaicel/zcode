Headers: `content-type`, `user-agent: opencode-failover-router/1.0`, `x-opencode-session` (relayed from client or persisted per-install UUID), `authorization: Bearer <key>`.
- **kind "messages" exists** (`messagesChat`, line 236): appends `/messages`, translates chat→Anthropic Messages (`toMessagesRequest` in anthropic-messages.mjs: system/developer messages hoisted to top-level `system`, `max_tokens` defaulted to 8192). Auth is dual: still sends `Bearer` via `upstreamHeaders` plus `x-api-key: <key>` and `anthropic-version: 2023-06-01` (comment: zen rejects Bearer-only on this endpoint with bare 403). SSE replies are translated back to OpenAI chunks (`MessagesStreamTranslator`); non-stream via `messagesToChatCompletion`.
- **kind "responses"** (`responsesChat`): appends `/responses`, Bearer key, same UA/session headers. **kind "codex"** (`codexChat`): OAuth token from `openai-oauth.mjs` (`CODEX_BASE = https://chatgpt.com/backend-api/codex`), appends `/responses`, adds `chatgpt-account-id` header, one forced token-refresh retry on 401.

## 3. Z.ai endpoint research

Official Z.ai docs ([docs.z.ai/devpack/quick-start](https://docs.z.ai/devpack/quick-start)) "Endpoint Guide" for Coding Plan keys confirms **three endpoints**:
- OpenAI Chat Completions: **`https://api.z.ai/api/coding/paas/v4`** (exactly what failover.json uses)
- Anthropic Messages: `https://api.z.ai/api/anthropic`
- OpenAI Responses: `https://api.z.ai/api/v1`

Standard pay-per-token API is a separate base URL `https://api.z.ai/api/paas/v4` (that's the failover.json `zai` provider); China mainland equivalents are `open.bigmodel.cn/api/coding/paas/v4` and `/api/paas/v4`. Overview ([docs.z.ai/devpack/overview](https://docs.z.ai/devpack/overview)) states the plan officially supports Claude Code plus Cline, OpenCode, and others (full list at docs.z.ai/devpack/tool/others) — coding-plan keys are routinely used with generic OpenAI-compatible clients and third-party usage trackers; no documented client-tool restriction was found.

**ZCode Start Plan / zcode-plan entitlement outside the ZCode app: no documented API path exists.** Nothing in Z.ai docs or web results describes using the ZCode desktop app's account-based entitlement (`zhipu-coding-plan-api-key` access type in provider_config.json) through a public endpoint; the documented route is a plan key from the Z.ai API-key console used against `https://api.z.ai/api/coding/paas/v4`. The keys found on this machine support that reading: the ZCode app holds its own 49-char coding-plan-format key distinct from the user's personal Z.ai key.
